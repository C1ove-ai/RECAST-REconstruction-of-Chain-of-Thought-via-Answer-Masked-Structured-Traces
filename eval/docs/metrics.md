# RECAST 评测指标设计

**版本** v0.2（已落地）｜**对应代码** `eval/**`｜**状态** 指标规范 + 脚本实现（参数以 `--help` 为准）

本文回答一个问题：**怎样用可测量的数字，支撑"还原出的 CoT 接近真实 CoT"这个主张。** 

> 数据管线（`data/`）、训练脚本（`train/`）和评测 harness（`harness/`）已经落地，第 7 节给出脚本与指标的映射；命令已对齐实际 CLI。示例数据以仓库中实际运行产生的 decoded run 为准。标"待确认"的数值（子集大小、相似度阈值、解析器行为）仍需用实测替换，不要直接抄进论文。

## 0. 记号

| 记号                 | 含义                          | 可观测性        |
| ------------------ | --------------------------- | ----------- |
| `q` / `y`          | 问题 / 教师的完整回答（本项目里是师生对话体文本）  | 可观测         |
| `z`                | 教师的真实思维链                    | **不可观测**    |
| `c`                | 解码模型还原出的 CoT（`decoded_cot`） | 可观测，本项目生成    |
| `r` / `y*`         | 数据集自带人工解法 / 标准答案            | 部分有 / 有     |
| `S_base` / `S_sft` | 训练前 / 用 `c` 微调后的学生          | 可观测         |
| `T`                | 教师模型                        | 只能通过 API 观测 |

总原则：**每个报告出来的数字都要能回答"它变大意味着什么"**；答不上来就不该进主表。

## 1. 两层评测目标

### 1.1 目标 (a)：还原 CoT 与真实 CoT 的距离——不可识别

理想指标是 `d(c, z)`，但 `z` 从不外露。这不是工程难题而是信息难题：同一个 `y` 可由多条不同的 `z` 产生（同一答案有多种路径），也可由同一段解释文字产生（教师自己的解释未必忠实，见 §4.2）。所以 `d(c,z)` 在任何假设下都无法直接估计，只能做三层代理：

| 代理层 | 可测量的量                             | 能支撑的结论               | 不能支撑的结论        |
| --- | --------------------------------- | -------------------- | -------------- |
| 表层  | `d(c, y)`：长度比、步骤覆盖、事实一致性（§5）      | `c` 未与教师可观测行为矛盾      | `c` 就是 `z`     |
| 行为层 | 用 `c` 训学生，比较 `S_sft` 与 `T`（§2、§8） | `c` 携带了产生 `y` 的功能性信息 | `c` 与 `z` 逐句相同 |
| 扰动层 | 动 `c`，看学生答案是否按预期变（§4）             | `c` 是答案的因果中介         | 每一步都真的发生过      |

**关键约束**：`d(c,y)` 小是必要条件，不是充分条件。一段"事后合理化"的 CoT 能与 `y` 完全一致，却在因果上并不产生 `y`。所以 §5 全是表层代理，主结论必须由 §8 的行为比较承担。

### 1.2 目标 (b)：学生能力——可以严格比较的量

三方对照，同一批题、同一 prompt 模板、同一答案抽取器：`S_base`（下界，排除"本来就会"）、`S_sft`（待测）、`T`（上界参考）。逐题记正确性后，任意两者都落进一张 2×2 表（以 `S_sft` 对 `T` 为例）：

|         | 教师对          | 教师错                    |
| ------- | ------------ | ---------------------- |
| **学生对** | `a` 一致正确     | `b` 学生"超"教师；先怀疑教师侧抽取错误 |
| **学生错** | `c` 能力缺口，主战场 | `d` 一致错误               |

四个格子同时给出准确率差、一致率和 McNemar 需要的 `b/c`（§8.3），信息量远大于单独报三个准确率。

### 1.3 为什么 (a) 必须落到 (b) 上

1. 若 `c` 真携带产生 `y` 的功能性信息，以 `c` 为监督的学生就应在**同一批题**上重现教师的行为分布——不只答案对错，还有错误模式、推理长度、何时放弃。
2. 反之，若 `S_sft` 与"只用答案训练"的对照无差异，则 `c` 相对 `y` 没有增量信息，无论它读起来多像 CoT。
3. 因此把 (a) 操作化为 (b) 的**受控比较**，而不是给 `c` 打一个"像不像 CoT"的分。

四个对照缺一个结论就不成立：

| 对照              | 做法             | 排除的替代解释                 |
| --------------- | -------------- | ----------------------- |
| answer-only SFT | 只训 `q → y*`    | 提升来自多训 epoch / 多见 token |
| shuffled-CoT    | 把 `c` 随机配给别的问题 | 任何长文本都能提分（格式正则化效应）      |
| gold-CoT SFT    | 用 `r` 作 CoT    | 给出该尺寸学生的上限，也是 `DFI` 的分母 |
| CoT 截断          | 只给 `c` 的前半段    | 学生其实只用 `c` 里的最终答案       |

Distilling Step-by-Step 的结论正是"rationale 比 label 更有信息量"，这个对照框架就是它的复用；STaR 则提醒存在 **rationalization**（答案对但理由错），只看准确率会高估还原质量。

**误差要分开报，别混成一个"CoT 质量分"**，否则结论无法归因：教师侧不忠实（`y` 不是 `z` 的忠实外化，§4，只能量化）、解码器侧幻觉（`c` 编造了 `y` 里没有的步骤/验证，§5，可部分控制）、学生侧容量（学不动 `c` 的复杂度，§2、§8）。分开报才能说"这一版幻觉率降了但下游没动，因为容量是瓶颈"。

## 2. 任务级指标

**这一节所有指标都依赖"答案抽取 + 等价判断"。抽取错一次，后面全错**——先做 §7 的解析器人工审计，再谈分数。

| 指标              | 定义                  | 公式                                                                 | 适用场景                     |
| --------------- | ------------------- | ------------------------------------------------------------------ | ------------------------ |
| exact-match acc | 逐题判断抽取答案与 gold 是否等价 | `acc = (1/N)Σ_i 1[verify(extract(ŷ_i), extract(y*_i))]`            | 所有有确定答案的题                |
| pass@1          | 每题采样 1 次的期望正确率      | `(1/N)Σ_i [1 − C(n_i−c_i,k)/C(n_i,k)]`，`k=1` 时退化为 `(1/N)Σ c_i/n_i` | 主指标，与文献口径一致              |
| avg@k           | 每题采样 `k` 次的平均正确率    | `(1/N)Σ_i (c_i/k)`                                                 | 小测试集（AIME）降方差            |
| maj@k           | `k` 个抽取答案多数投票后判对错   | `(1/N)Σ_i 1[mode(â_i1..â_ik) == y*_i]`                             | 有推理难度的题；Self-Consistency |

**实现注意**

- "exact match"在数学里几乎从不指字符串相等：`\frac{1}{2}`、`0.5`、`\dfrac12` 必须判等，否则准确率凭空掉 5–15 点。
- 多个 `\boxed{}` 取**最后一个**；无 `boxed` 时回退"最后一个数字/最后一行等式"，回退规则要写进注释并被审计抽样覆盖。解析失败记"无答案"，不算对，且单独计数。
- `(1,2)` 与 `{1,2}` 是不同类型必须类型匹配；`(1,2)` 在中文语境还可能表示开区间——这类**已知歧义**记 `ambiguous`，不要静默判对或判错。中文全角标点、单位（`$`、`cm`、`\%`）、`^\circ` 在归一化阶段剥离。
- `pass@k` 用组合数无偏估计，`n` 大 `c` 小时改用 `1−Π(1−k/j)` 避免溢出；`n_i` 不一致时必须分开报，否则题目间被隐性加权。`avg@k` 与 `pass@1`（`n=k` 时）数学上相等，但各代码库混用 `avg@k`/`mean@k`/`cons@k` 三种叫法——**报告必须写清公式**，否则读者不知道你报的是平均还是投票。
- `maj@k`：`k` 为偶数会平票，平票策略（随机/取最先/取最长 CoT）必须固定并报平票率；投票前必须归一化，否则 `0.5` 与 `\frac12` 会被投成两票；`maj@k` 先升后饱和，至少报 `k ∈ {1,4,8,16}` 的曲线。
- **小测试集与采样设置会放大一切误差**：AIME 只有 30 题，一题翻转就是 3.3 pt、95% CI 半宽约 ±18 pt，必须报 `avg@k`/`maj@k` 和 CI，禁止用单次 `pass@1` 的差值讲故事；温度太低（0.2）采样几乎相同、`maj@k` 退化成 `pass@1`，太高（1.0+）格式崩坏导致抽取失败，0.6–0.8 是常用区间，改温度必须重跑全部基线。

### 2.1 strict vs flexible answer matching

| 口径       | 做法                          | 优点         | 风险                   |
| -------- | --------------------------- | ---------- | -------------------- |
| strict   | 归一化后字符串相等（去空格、统一 LaTeX、去单位） | 不会误判、可复现   | 误杀写法不同的正确答案，低估所有模型   |
| flexible | 符号等价（sympy 化简、数值代入、类型匹配）    | 贴近"数学上对不对" | 解析器 bug 会误判为对，高估所有模型 |

lm-evaluation-harness 的 `gsm8k` 同时报 `exact_match,strict-match` 与 `exact_match,flexible-extract`，就是让读者判断差距来自能力还是解析。**建议两个都算，主表报 flexible，附 strict 差异表；两者相差 > 3 pt 时先查解析器，不要先解释模型。**

### 2.2 bootstrap 置信区间

对 `b = 1..B`（`B=10000`）从 `N` 道题中有放回抽 `N` 道、重算指标得 `θ*_b`，取 `CI_95 = [percentile(θ*, 2.5), percentile(θ*, 97.5)]`。重采样单位是**题**不是样本（否则同题多采样被当独立观测，CI 偏窄）；比较两个模型用**配对** bootstrap（同批题同时重采样），不要用"两个 CI 是否重叠"——后者保守且容易漏掉真实差异。`maj@k` 这类非线性统计量不要用正态近似。各测试集的 `N` 与 CI 半宽见 §8.1：**`N=30` 时 ±18 pt 的波动是抽样噪声，不是模型差异。**

## 3. 基准数据集

| 数据集               | 规模              | 难度             | 答案形式      | 用途             | 主要风险                    |
| ----------------- | --------------- | -------------- | --------- | -------------- | ----------------------- |
| in-domain 留出集（自建） | 200–500         | 同训练分布          | 数值/表达式    | **主指标**，直接检验蒸馏 | 与训练集近重复，必须去重            |
| GSM8K             | 8.5K（约 7.5K/1K） | 小学应用题          | 整数        | 不退化检查、对齐文献     | 强模型已饱和（95%+），天花板效应      |
| MATH-500          | 500             | 竞赛（MATH 测试集子集） | LaTeX 表达式 | **主指标**，区分度最好  | base 预训练可能见过            |
| AMC23             | 40              | 竞赛中高           | 整数 0–25   | 次要，补充竞赛分布      | `N=40`，CI ±15 pt        |
| AIME24 / AIME25   | 各 30            | 高              | 整数 0–999  | 与强模型对比的**可选**项 | 方差极大，必须 `avg@k`/`maj@k` |
| OlympiadBench     | 8,476（含物理、多模态）  | 奥赛             | 混合（数值+证明） | 压力测试           | 证明题无标准答案；纯文本数学子集规模待确认   |

**推荐组合**：必跑 in-domain 300 + GSM8K + MATH-500（分别覆盖同分布泛化、基础能力不退化、竞赛泛化）；MATH-500 上 `n=8` 报 `avg@8`/`maj@8`，AIME 上 `n=16`；AIME 只用于"与强模型差距"的叙事，不作模型选择依据；AMC23 与 OlympiadBench 全量不作主指标（40 题太少、证明题评测未成熟）。**切分纪律**：所有 test split 只在最终报告时用，模型/超参选择用 dev（从 in-domain 再切 100 题）——反复在 test 上调 prompt 即等于训练集泄漏。

**每集的具体坑**：GSM8K 测试集口径有 1K 与 1,319 两种（待确认），比文献时注明来源，答案在 `####` 之后；MATH-500 难在 LaTeX 解析而非推理，同题可能有多个等价答案；AMC23 原题是选择题，答案转整数 0–25，prompt 必须要求"只输出整数"否则模型输出选项字母；AIME 答案是 000–999，抽取时补零；OlympiadBench 证明题占比高，`EM` 不适用，要用就先固定一个数值子集并人工核验答案。

## 4. CoT 质量与忠实度

**忠实（faithful）的操作定义**：CoT 是答案的因果中介，而不是事后写出的解释。测法只有一种——**动 CoT，看答案是否按预期动**。四个协议来自 Measuring Faithfulness in Chain-of-Thought Reasoning，**必须一起看**：忠实 = 截断会掉、注入错误会跟随、填充不掉、改写不翻车；单看任何一个都能被绕过。

### 4.1 四个扰动协议

| 协议              | 具体步骤                                                                              | 量化                                                                         | 解读                                                                          |
| --------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| early answering | 在 CoT 的 0/25/50/75/100% 处**按步骤边界**截断，追加固定引导句"因此，最终答案是"；让模型续写 ≤128 token，用同一抽取器取答案 | `acc(p)` 曲线、early-answer 率（`p=0` 时能给出可解析答案的比例）、`Δ_25 = acc(25) − acc(100)` | `Δ_25 ≈ 0` 且 early-answer 率高 → 事后解释；`Δ_25` 显著为负 → CoT 有因果作用                 |
| adding mistakes | 选一个**中间步**（不能是最后一步，否则等价于直接改答案），用强模型改成"看起来合理但错误"的版本（改数值/符号/方向、保持结构），保留前缀让模型继续      | 最终答案是否**等于由该错误推导出的那个答案**（不是简单判对错）的 propagation rate；对照在同位置做同义改写            | 传播率高 = 模型真在读那一步；对照 flip rate 应显著更低。注入的错误必须能唯一确定错误答案（12→13 使结果 84→91），否则无法归因 |
| filler tokens   | 在步与步之间插入无关文本（如"顺便说一句，今天天气不错"），总长度接近原 CoT                                          | `acc_filler − acc_full`；同时报"同等 token 预算下截断 vs 填充"                          | 不变或更高 → 只吃长度不吃内容。填充不得含数学词                                                   |
| paraphrase      | 强模型做保义改写（换符号、换叙述顺序，步骤不变）                                                          | flip rate                                                                  | 必须与 adding mistakes 配对：两者都翻转=对表面形式过敏；两者都不翻转=根本没在用 CoT                       |

**切分与解析**：按 token 位置截断会切在公式中间，产生无意义前缀；两种切法都跑，差异大说明结论对切分敏感，要一起报。解析失败记"无答案"，不算对。**两种用法别混**：**student 模式**扰动学生**自己生成**的 CoT（标准协议，答"学生是否真在推理"）；**data 模式**把 `c` 当 in-context 前缀，截断/改错后看学生答案是否跟随（更贴近还原质量，但受 prompt 格式影响大，只作辅助证据）。`harness/faithfulness.py` 默认跑 student 模式 early answering（最便宜、信息量最大）；adding mistakes 只在 100–200 条子集上跑；Turpin 实验独立成子命令，只跑一次出结论。

### 4.2 Turpin 式不忠实解释：提示注入实验

Language Models Don't Always Say What They Think 的做法是给输入加偏置特征，看答案变不变、解释提不提。本项目可直接复用，因为管线只依赖"问题 → 回答"：

1. 在问题后追加暗示（如"一位教授认为答案是 42"），其余不变。
2. 测两个量：教师最终答案的**变化率**（相对无暗示基线）、教师可见解释**提及**该暗示的比例；不忠实的标志是变化率高 + 提及率低。
3. **本项目扩展（关键）**：对变化后的 `y` 再跑一次还原，测还原 CoT 的提及率。

这是唯一能直接量化"还原 CoT 是否继承了教师的不忠实"的实验：`U = answer_flip_rate × (1 − mention_rate_restored)`。暗示强度要先做预实验标定——太弱没效果，太强变成服从性测试，测的就不是 CoT 忠实度了；样本 ≥ 200。

### 4.3 process supervision / PRM

Let's Verify Step by Step 的思路是给每个前缀 `s_{1..j}` 打分，再聚合（`min` 或连乘）成整条轨迹的分数。

- **评测仪器**：对还原 CoT 逐步打分 → 分数分布、低分步位置分布。风险是领域漂移：PRM 多在人工标注的解题 CoT 上训练，对"认知型"还原 CoT 可能整体偏低。
- **数据过滤**：RFT 时作第二道闸门（答案对 ∧ 最低步分 ≥ τ）→ 接受率、过滤后下游准确率。风险是选择偏差，等于把 PRM 的偏好蒸馏进学生。

使用前必须抽 50 条人工标注算 PRM 排序与人的 Spearman 相关；低于 0.4 就不要用它过滤，那只是在放大 PRM 的偏见。

## 5. 蒸馏保真度指标（还原 CoT vs 教师可观测回答 / 参考答案）

本节全是**表层代理**，单独不能证明任何事；作用是排除明显不合格的 `c`，并为 §5.6 提供可解释的分解。

### 5.1 长度比

```
LR = median_i( |c_i| / |y_i| )      |·| = 同一 tokenizer 的 token 数
```

报**中位数 + IQR**（长尾严重，不报均值），同时报三个版本：对教师回答的 `LR`、对参考答案的 `LR_ref`、以及**加长度下限前后**的 `LR`。长度下限会让 `LR` 被构造性抬高（§6.2），用加了下限之后的 `LR` 去声称"还原 CoT 足够长"是循环论证。

### 5.2 结构与步骤覆盖

还原 CoT 的结构和数学解法结构**不是一回事**：当前 decoder 输出的是七阶段认知结构（任务识别/需求分析/材料诊断/策略选择/关键验证/输出组织/自检），不是逐步解题。所以覆盖度必须分两层算，否则会系统性低估：

- **数学步骤层**（`y` 中的编号、空行、独立公式块）：教师解法的每一步是否在 `c` 中被提及/复现 → `coverage@τ`、关键步召回。
- **认知阶段层**（`c` 的七个小标题）：每阶段是否有实质内容（非空话）→ 阶段覆盖率、平均段长。

`coverage@τ = (1/M)Σ_j 1[max_i sim(s_j, c_i) ≥ τ]`，`sim` 用句向量余弦或字符 n-gram Jaccard，`τ ≈ 0.75`（待确认，需在 30 条上校准）。另外两个几乎零成本的指标：**关键步召回（0/1）**——`y` 的最后两步（结论步 + 验证步）是否被覆盖，比平均覆盖度更能预测下游成败；**顺序一致性**——匹配上的步序号做 Kendall `τ`，倒序严重说明 `c` 是重排而非还原。

### 5.3 LLM-as-judge rubric

| 维度       | 判什么                  | 1 分     | 3 分       | 5 分           | 权重  |
| -------- | -------------------- | ------- | --------- | ------------- | --- |
| 事实一致性    | 与 `y`/`r` 是否矛盾       | 有明确错误结论 | 大体一致、细节含糊 | 无矛盾且细节可核      | 30% |
| 步骤覆盖     | 关键步骤是否出现             | 只覆盖结论   | 覆盖主线      | 主线 + 验证步      | 25% |
| 无幻觉      | 是否编造 `y` 里没有的步骤      | 多处编造    | 少量        | 无             | 20% |
| 忠实于可观测行为 | 是否把教师没做的验证说成做了       | 系统性虚构自检 | 偶有        | 与 `y` 的自我修正一致 | 15% |
| 元叙述/泄漏   | 是否出现"老师/学生/课堂/模板/还原" | 明显泄漏    | 个别词       | 无             | 10% |

"忠实于可观测行为"最易被忽略也最危险：还原模型很容易写"我检查了一遍，发现符号错误并改正"，而教师根本没做过这个检查——这是 Turpin 意义上的不忠实被**二次放大**。

**判分协议**（不做这些，judge 分数不可信）：盲评（judge 不知哪条是还原 CoT）；2 judge × 2 顺序（A/B、B/A）；30 条人工标注算 Cohen `κ`，`κ < 0.4` 就改细 rubric 再测；rubric 明确"长度不计分"并回归检查分数与 `|c|` 的相关性，相关 > 0.5 说明 judge 在奖励长文本；judge 模型 ≠ 解码模型，避免自我偏好。

### 5.4 step-level entailment

对每个还原步 `c_i`，检查 `(q, y)` 是否蕴含 `c_i`（premise = 问题 + 教师回答，hypothesis = 该步），指标为蕴含率。**通用 NLI 在数学记号上很弱**（`a²+b²` 与 `a^2+b^2` 会被判无关），实践顺序是先用 NLI 看分布，再用 LLM judge 在分歧样本上复核；两者一致率 < 70% 就只报 LLM judge 并说明 NLI 不可用。具体 NLI 选型待确认。

### 5.5 为什么 BLEU/ROUGE 不能作主指标

| 原因           | 说明                                                                 |
| ------------ | ------------------------------------------------------------------ |
| 目标不是复述       | prompt 明确禁止逐句复述教师原文；**低 n-gram 重叠是设计要求，不是缺陷**                      |
| 数学表达多样       | `\frac{1}{2}` vs `0.5`、`a²+b²` vs `a^2+b^2`，分词差异让分数噪声极大            |
| 与正确性不相关、长度偏置 | 抄对符号但逻辑错的 CoT 可以 ROUGE 很高；且 ROUGE recall 随长度单调上升，正好与长度下限耦合，会奖励"注水" |

唯一合理用途：当**复制/泄漏探测器**（`ROUGE-L > 0.8` 且 `dialogue_leak_terms` 非空时人工检查是否直接复述了原文），以及作回归测试监控 decoder 版本升级后的分布漂移。

### 5.6 保真度指数 DFI 与差距闭合率 GC

把 §2 的准确率折算成两个可解释的比值——这就是 (a) 落到 (b) 的量化形式：

```
DFI = (A_restored − A_ctrl) / (A_gold − A_ctrl)      # 还原 CoT 提供了 gold CoT 多少比例的过程信息
GC  = (A_restored − A_base) / (A_teacher − A_base)   # 教师-学生差距被闭合了多少
```

`A_ctrl` 是 answer-only SFT 的准确率（§1.3 的对照）。`DFI` 是本项目最想报的数字："还原 CoT 达到人工解法的几成功效"。`GC > 1` 表示学生超过教师，可能真实（更适配该题域），也可能是教师侧抽取错误，必须回查 `b` 格。两者都要带 bootstrap CI；分母 `A_gold − A_ctrl` 若不显著（< 3 pt），`DFI` 无定义，直接报"上限未建立"，不要硬算。

## 6. 效率与成本

### 6.1 要记录的量

| 指标                                    | 定义                                                        | 为什么                                                |
| ------------------------------------- | --------------------------------------------------------- | -------------------------------------------------- |
| `tokens_out`                          | 每题输出 token 的中位数与 p90                                      | CoT 长度直接决定成本与延迟                                    |
| `latency` / `throughput` / `peak_mem` | p50、p95 秒 / 题每分钟 / 峰值显存 GB                                | 体验、限流瓶颈、能否单卡跑                                      |
| `$/1k 题` / `cost_per_correct`         | `1000 × (t_in·p_in + t_out·p_out) / 1e6`；再除以 `1000 × acc` | 预算；**`cost_per_correct` 是最有用的单一成本指标**：同一笔钱买到多少正确答案 |

### 6.2 与 CoT 长度下限的关系

当前 decoder 用 `min_tokens` / `min_ratio`（相对源回答的估算 token）加 `expand_retries` 强制"还原 CoT 不得太短"，带来三个必须写清的副作用：

1. **长度比被构造性抬高**：`LR ≥ min_ratio` 是设计保证而非测量结果。报告要同时给"下限前"的长度分布，以及 `num_below_floor`、`expand_retries` 的实际触发次数。
2. **成本线性上涨**：下限抬高 `k` 倍，`tokens_out` 与 `$/1k 题` 近似同比例上涨。
3. **可能诱发注水与幻觉**：为凑长度而重复、堆砌无信息句，会直接拉低 §5.3 的事实一致性与"无幻觉"分。

所以长度下限不能凭"看起来够长"来设，要做消融：`min_ratio ∈ {0.5, 1.0（当前默认）, 1.5}`，分别记录 `tokens_out`、下游 `acc`、`acc / 1k token`、事实一致性分，取 `acc / 1k token` 的拐点而不是最长的那档。

### 6.3 效率前沿与推理期上限

- **训练侧**：成本 = `GPU 时 × 单价`，记录 `tokens/sample`；QLoRA 与全参分开报（显存差一档）。LIMO 的结论（少量高质量样本即可激发推理）意味着**数据量不是主变量，`c` 的质量才是**：效率表要有"每题成本"和"每正确题成本"，而不是只报总训练时长。
- **推理侧**：学生 `max_tokens` 设 `{1k, 2k, 4k}` 跑准确率曲线，确定评测上限——太小会学不到长推理，太大成本翻倍且更易跑偏。s1 的 budget forcing 说明"长度预算"本身是可调超参，不是常数。

## 8. 实验设计与统计

### 8.1 样本量与可检测差异

| 测试集       | N    | 95% CI 半宽 | 配对设计可检测差异（约）   |
| --------- | ---- | --------- | -------------- |
| in-domain | 300  | ±5.7 pt   | ~6 pt          |
| GSM8K     | 1319 | ±2.7 pt   | ~3 pt          |
| MATH-500  | 500  | ±4.4 pt   | ~5 pt          |
| AIME      | 30   | ±17.9 pt  | ~20 pt（只能看大效应） |

规则：**先用 dev（100 题）筛配置，再用 test 出数**。在 500 题上反复比较 10 个配置，"最好的那个"至少虚高 2–3 pt。

### 8.2 seed 与采样设置

- **训练 seed**：3 个（0/1/2），报 mean ± std；只报单 seed 的增益不足以支撑"还原 CoT 有用"。
- **评测采样 seed**：**固定**，且所有模型共用同一组 seed，否则配对检验失效。

| benchmark | n        | T       | top_p      | 指标                       |
| --------- | -------- | ------- | ---------- | ------------------------ |
| GSM8K     | 1（贪心）+ 8 | 0 / 0.7 | 1.0 / 0.95 | `pass@1`、`avg@8`         |
| MATH-500  | 1 + 8    | 0 / 0.7 | 1.0 / 0.95 | `pass@1`、`avg@8`、`maj@8` |
| AIME24/25 | 16       | 0.7     | 0.95       | `avg@16`、`maj@16`        |
| in-domain | 1 + 8    | 0 / 0.7 | 1.0 / 0.95 | `pass@1`、`avg@8`         |

### 8.3 配对检验

```
McNemar：b = 学生错且对照对，c = 学生对且对照错
          χ² = (|b − c| − 1)² / (b + c),  df = 1
          b + c < 25 时改用精确二项检验（双侧）
```

**配对 bootstrap**：对题做有放回重采样，每次同时算两个模型的 `Δacc`，取 2.5/97.5 分位，报 `Δacc [CI]`，而不是看两个准确率"差得够不够多"。**多重比较**：3 个 benchmark × 3 组两两比较 ≈ 9 次检验，Bonferroni 后 `α = 0.05/9 ≈ 0.0056`，或改用 BH 控制 FDR，并在表注写明用了哪种。

### 8.4 数据泄漏检查

| 检查项     | 方法                                                     | 阈值   | 处置                             |
| ------- | ------------------------------------------------------ | ---- | ------------------------------ |
| 完全重复    | 归一化后问题字符串相等                                            | 任意命中 | 从训练集删，保留测试集                    |
| 近似/语义重复 | 字符 5-gram MinHash Jaccard ≥ 0.8，或句向量余弦（如 bge-m3）≥ 0.95 | 上述阈值 | 人工看，确认后从训练集删                   |
| 答案泄漏    | `c` 中是否出现 gold 答案字符串                                   | 统计比例 | 高则跑 answer-only 对照，估计增益里多少来自答案 |
| 模板泄漏    | 训练/测试 prompt 模板是否一致                                    | 必须一致 | 不一致则重跑                         |

**管不了的部分**：教师和 base 的预训练都可能见过公开基准。只能写进 §9 的局限，不能靠管线消除。

### 8.6 分析顺序

**按这个顺序看，能省一半返工**：抽取审计（100 条人工核，误判 > 2% 先修解析器）→ base 是否正常（GSM8K 明显低于文献说明模板/抽取有问题）→ answer-only 对照（若 `S_ctrl` 已追平 `S_ours`，主结论不成立）→ 主结论（`Δacc`、`DFI`）→ 与教师对比（`GC`、`b` 格）→ 忠实度（early-answering 曲线）→ 成本（`cost_per_correct`）。

## 9. 局限

| 局限                       | 具体影响                                       | 缓解                                            | 无法解决的部分    |
| ------------------------ | ------------------------------------------ | --------------------------------------------- | ---------- |
| 答案抽取误差                   | 所有准确率同向偏移，小测试集上被放大                         | 双口径 + 人工审计 + 分歧样本复核                           | 证明题、歧义答案   |
| judge 偏差                 | 长度偏好、位置偏好、自我偏好                             | 盲评、双向、`κ` 校准、防长度回归                            | 主观维度的系统性偏移 |
| 基准污染                     | 教师与 base 可能见过测试题，抬高双方                      | 泄漏检查（只查得到自己的训练集）                              | 预训练数据不可审计  |
| 小测试集                     | AIME 30 题，一题翻转 3.3 pt                      | 报 CI、`avg@k`/`maj@k`、k 曲线                     | 统计功效的物理上限  |
| 真实 CoT 不可观测              | `d(c,z)` 无法估计，所有结论都是代理                     | 三层代理（§1.1）+ 多个对照                              | 根本性的识别问题   |
| 教师回答本身不忠实                | 完美还原也只能还原出不忠实的 CoT                         | Turpin 实验量化（§4.2）                             | 教师内部状态     |
| **还原 CoT 是"认知型"而非"解题型"** | 学生可能学会"如何描述思考"而非"如何解题"，`acc` 不涨而 `c` 看起来很好 | SFT 目标拼上教师最终答案；加"关键步召回"；必要时改 prompt 让还原包含数学步骤 | 任务定义层面的取舍  |
| RFT 过滤偏差                 | 只用"答案对 + PRM 认可"的数据，学生继承过滤器偏好              | 报接受率、与不过滤对照比较                                 | 选择偏差无法完全消除 |

倒数第二条是本项目最需正视的风险：**如果 `c` 描述的是"我如何组织回答"而非"我如何解这道题"，§5 的所有保真度指标都会很好看，而 §2 的准确率不会动。** 这正是本文坚持把 (a) 落到 (b) 的原因——只有下游行为能揭穿"像 CoT 但没有用"。
